# Swift SDK 통합 원칙

재사용 가능한 SDK는 호스트 앱이 자신의 저장소와 권한을 계속 소유할 수 있게 해야 한다. 문서 기능을 추가하려는 앱이 다른 앱의 기본 자료함, 계정 기록, 이관 규칙까지 함께 가져오게 해서는 안 된다.

## 정본과 복구본의 책임

Markdown 원문은 문서의 정본이다. 검색 색인은 원문에서 다시 만들 수 있는 파생 자료다. 편집 중인 초안은 원문과 별도로 보관하며, 저장할 때는 편집의 기준이 된 원문 버전이 아직 유효한지 확인한다.

외부에서 원문이 변경되면 초안을 보존하고 새 원문을 다시 읽는다. 오래된 내용을 조용히 덮어쓰는 것보다 사용자가 변경을 검토하고 결정을 내릴 수 있게 하는 편이 안전하다. 자동 병합을 사용하더라도 병합을 검토한 시점 이후의 변경을 다시 확인해야 한다.

## 호스트가 결정할 사항

- 원문 폴더에 대한 접근 허용과 보안 범위의 수명
- 색인과 초안을 보관할 전용 디렉터리와 계정 구분
- 백그라운드 전환과 계정 변경 시 세션 종료 시점
- 앱의 iCloud 컨테이너, App Group, 서명과 개인정보 설정
- 기존 자료의 이관을 실행할지 여부와 충돌 시 복구 절차

UI는 이 계약 위에 선택적으로 놓인다. 같은 세션을 사용하는 앱은 자신의 탐색과 표시 방식을 유지하면서 문서 읽기와 안전한 저장을 사용할 수 있어야 한다.

## 패키지 배포

개발자 컴퓨터의 경로에 의존하는 패키지는 깨끗한 소비 환경에서 재현하기 어렵다. SDK의 의존성 그래프는 저장소 안의 명시적인 타깃과 버전이 정해진 원격 의존성으로 구성하고, 앱 전용 연동은 별도 경계에 둔다.

리소스는 호스트의 메인 번들을 추측하지 않고 패키지의 `Bundle.module`로 읽는다. 이 예제의 문서는 읽기 전용 리소스이며, 사용자가 자료함 만들기를 선택할 때 새 디렉터리에만 복사한다.
