# 팀 문서 운영 절차

문서가 오래 유지되려면 최신 내용을 쓰는 일과 이전 판단을 보존하는 일을 함께 다뤄야 한다. 프로젝트의 설계 문서에는 해결하려는 문제, 선택한 방법, 버린 대안, 판단의 근거를 기록한다.

## 변경을 제안할 때

먼저 수정하려는 문서와 기준 버전을 확인한다. 작은 문장 교정과 계약 변경을 구분하고, 동작에 영향을 주는 변경에는 어떤 사용 흐름이 달라지는지 적는다. 아직 검증하지 못한 내용에는 그 이유를 명시한다.

변경 중 원문이 갱신되면 작업 중인 초안을 별도로 보존한다. 새 원문을 읽고 양쪽 변경을 검토한 다음 저장한다. 충돌 해결이 불확실하면 임의로 한쪽을 선택하기보다 초안과 원문을 둘 다 보관한다.

## 검토 기록

검토자는 문장의 표현뿐 아니라 주장과 근거의 연결을 확인한다. 구현이 존재하는지, 실제 실행으로 확인했는지, 아직 목표인지를 구분한다. 자동 검증은 변경의 중요한 실패를 잡는 데 필요한 범위로 제한한다.
