# 문서 관리

현재 자료함 이름을 눌러 자료함을 전환합니다. 문서 목록의 **더 보기 → 폴더·태그**을 누르면 폴더·태그로 찾아볼 수 있습니다. 조건이 있으면 실제 범위와 해제 동작을 표시합니다. 돋보기를 누르면 목록 위에 검색창이 열립니다. 문서를 읽고 뒤로 돌아와도 검색어와 범위를 유지합니다.

긴 자료함·문서 제목과 폴더 위치는 줄바꿈해 표시합니다. 목록에는 짧은 발췌를 두 줄 이내로 보여 주고, 전체 내용은 문서를 열어 읽습니다. 문서 정보의 긴 제목·태그·파일 경로도 줄바꿈합니다.

폴더를 정리할 때는 iPhone의 **더 보기 → 문서 정리**, Mac 문서 목록의 **더 보기 → 문서 정리**를 엽니다. 자료함 선택 화면의 현재 자료함 아래에서도 **문서 정리**로 들어갈 수 있습니다. **새 폴더**로 현재 위치 아래 폴더를 만들고, 항목 메뉴에서 **이름 변경**, **이동**, **휴지통으로 이동**을 선택합니다. 문서 목록의 컨텍스트 메뉴와 본문의 문서 옵션에서도 같은 작업을 실행합니다. 새 문서를 만들 때 저장할 폴더를 선택할 수 있습니다.

파일 이름 변경은 Markdown의 첫 제목과 별개입니다. 파일 확장자는 유지해야 합니다. 이동과 폴더 관리는 현재 자료함의 `notes/` 아래에서 수행하며, 자료함 정체성 파일과 `notes/` 자체는 이동·삭제할 수 없습니다.

## 바로 작성하기

목록의 작성 버튼 또는 Mac의 Cmd-N으로 새 문서를 만들고 바로 편집합니다. 제목과 본문을 입력하고 명시적으로 저장합니다. 기존 초안은 다른 문서를 만들어도 보존합니다. 생성 결과가 미확정이면 같은 요청의 결과를 확인하며 자동으로 다시 만들지 않습니다. 대상 자료함·폴더와 제목을 먼저 지정하려면 **더 보기 → 새 문서 옵션**을 엽니다.

## 제목과 태그

문서 옵션의 **제목·태그 편집**에서 표시 제목과 태그를 함께 저장합니다. 제목을 바꾸면 첫 Markdown 제목의 내용을 바꾸며 원래 제목 레벨을 유지합니다. 제목이 없을 때 새 제목을 지정하면 본문 앞에 추가합니다. 태그만 바꾸는 경우 기존 제목의 서식이나 제목 없는 본문은 그대로 둡니다.

태그는 원문의 YAML `tags`에 문자열 배열로 저장합니다. 기존 문자열 한 개도 하나의 태그로 읽습니다. 양끝 공백을 제거하고 Unicode NFC로 정규화하며, 대소문자가 다른 중복은 첫 표기를 유지합니다. 입력은 최대 64개, 정규화한 태그 하나는 UTF-8 128바이트 이하여야 합니다. 숫자처럼 보이는 태그는 YAML에서 문자열로 인용해야 합니다. 숫자·null·맵 같은 값은 원문 진단으로 표시하며 편집 내용을 자동 폐기하지 않습니다.

제목과 태그 변경은 한 원문 저장으로 처리합니다. 문서 ID·다른 YAML 필드·주석·본문·줄바꿈을 보존하고, 편집 화면을 연 뒤 외부에서 원문이 바뀌면 덮어쓰지 않습니다. 이전 DB에 태그 필드가 없더라도 다음 원문 읽기에서 기존 태그를 다시 해석합니다. 태그를 모두 제거하면 해당 YAML 필드를 제거합니다.

## 필터와 전체 검색

목록의 **더 보기 → 폴더·태그**을 눌러 **찾아보기**에서 폴더·태그를 선택합니다. 선택한 이름은 목록에 표시되며 해제 동작으로 초기화합니다. 문서에 유형이 있거나 유형 조건이 선택돼 있으면 문서 유형도 선택할 수 있습니다. 폴더는 하위 폴더를 포함하며 비슷한 이름의 다른 폴더는 포함하지 않습니다. 태그는 Unicode NFC·대소문자 정규화 키로 비교하고 문서 유형은 원문의 값을 사용합니다. **유형 없음**과 **모든 유형**을 구분합니다. 같은 조건이 일반 문서 목록과 검색에 적용되며 창마다 독립적으로 유지됩니다.

검색은 로컬 원문의 제목·별칭·섹션 내용과 FTS 결과를 합쳐 순위를 정하고, 필터를 적용한 전체 결과에서 50개씩 표시합니다. **검색 결과 더 보기**로 끝까지 확인할 수 있으며 전체 결과 수와 현재 표시 수를 함께 보여 줍니다. 한 문서의 서로 다른 섹션은 별도 검색 결과입니다. 앱의 전체 검색과 별개로 SEMI의 기존 제한 검색·선택적 의미 검색 계약은 유지합니다.

다음 페이지는 검색어·필터·페이지 크기·원문 버전에 연결됩니다. 도중에 원문이 바뀌면 오래된 결과를 이어 붙이지 않고 새 검색을 안내합니다. 다음 페이지 읽기 실패 시 이미 읽은 결과는 유지하고 재시도할 수 있습니다. 읽지 못한 원문이 있으면 부분 검색임을 표시하며 복구 항목으로 연결합니다. 검색 DB는 원문에서 다시 만들 수 있는 파생 데이터입니다.

## 삭제와 복원

삭제한 문서·폴더는 원문 자료함의 `.folio-trash/<UUID>/`에 원래 경로·버전 기록과 함께 보관합니다. 문서 관리의 **휴지통**에서 원래 위치로 복원할 수 있습니다. 같은 경로의 파일이 있으면 덮어쓰지 않습니다. 원래 상위 폴더를 삭제했다면 폴더를 먼저 복원하거나 다시 만든 뒤 문서를 복원합니다.

휴지통은 문서 목록·검색·원문 ZIP에 포함되지 않습니다. 문서를 삭제해도 첨부는 유지하므로 다른 문서의 공유 참조를 훼손하지 않습니다. 들어오는 링크는 원문에 남고 대상이 없는 연결로 표시되며, 같은 문서를 복원하면 다시 연결됩니다. 영구 삭제는 휴지통 항목에서 대상을 확인한 뒤 실행하며 되돌릴 수 없습니다.

손상된 휴지통 기록은 확인이 필요한 항목으로 표시합니다. 정상 항목 조회는 계속 가능하고 손상된 항목을 자동 삭제하지 않습니다. Folio가 기록하지 않은 파일과 숨김 메타데이터도 보존합니다.

## 편집과 이동의 경계

**편집**에서는 문서 본문을 수정합니다. ID·태그 같은 YAML 속성은 기본 본문 편집에서 감추고 원래 bytes를 유지합니다. 제목·태그는 별도 편집 화면을 사용합니다. 명시적 **저장**이 성공하고 더 새로운 입력이 없을 때 읽기로 돌아갑니다. 저장 중 새로 입력한 내용은 초안으로 유지합니다. **미리 보기**는 초안을 저장하지 않고 보존합니다. Mac에서는 Cmd-S로 저장할 수 있습니다.

미저장 초안이 있을 때 문서 정보에서 **원문 버전**을 펼쳐 확인하면 그 버전을 창 사이에 공유되는 해당 초안의 저장에 사용합니다. 확인 뒤 원문이 다시 바뀌면 자동 병합하거나 덮어쓰지 않고 초안을 보존합니다. 문서 정보를 다시 열어 현재 원문 버전을 확인한 뒤 저장을 다시 요청할 수 있습니다. 초안의 기준 원문과 현재 문서가 같으면 별도 확인 없이 저장할 수 있으며, 기준이 다르고 확인된 버전이 없으면 문서 정보를 먼저 확인해야 합니다. 앱을 다시 열어 확인 정보가 사라진 경우에도 같은 조건이 적용됩니다.

열린 모든 창의 편집·복구·버전 비교를 마친 뒤 파일을 정리합니다. 저장하지 않은 초안을 자동 저장하거나 버리지 않습니다. 대상이 확인 이후 변경되면 작업을 거부하고 다시 확인하도록 안내합니다.

초안 폐기 확인은 캡처한 대상 값 하나로 표시 여부를 결정합니다. 확인 버튼도 그 값을 사용해 현재 자료함·문서·편집 내용을 다시 확인하므로, 확인 창이 닫히면서 표시 상태를 비워도 폐기 대상이 바뀌지 않습니다.

명시적 문서 ID는 이동해도 유지합니다. 경로 기반의 기존 문서는 새 경로 ID로 바꾸고 창의 선택·탐색 기록도 함께 갱신합니다. 이동하는 문서의 상대 링크·첨부 경로와 다른 문서에서 들어오는 상대 링크를 조정합니다. 일반적인 참조형 링크는 영향을 받는 사용 위치를 제목·레이블을 유지하는 인라인 링크로 변환하며, 원래 정의는 보존합니다. 코드 블록과 인라인 코드의 예시는 수정하지 않습니다. 원문 메타데이터가 잘못되어 링크를 검증할 수 없으면 먼저 복구해야 합니다.

빈 폴더는 원문 ZIP 내보내기·가져오기에서도 유지합니다. 심볼릭 링크·특수 파일·미수신 iCloud 원문·충돌 중인 파일은 정리 작업의 대상으로 사용하지 않습니다. 폴더의 준비 한도는 파일 2,048개, 전체 항목 8,192개, 256 MiB, 깊이 32단계입니다. Markdown은 256 KiB 이하입니다.

## 구현 경계

`WikiFileAction`은 선택 당시의 자료함 context·대상·revision을 담고, `command(name:destination:)`에서 파일 이름을 검사해 명령을 만듭니다. 앱 모델은 초안 checkpoint 뒤 명령을 준비하고 `FolioDocumentLibrary`의 변경 작업에 진입합니다. 진입한 호출부의 `defer`가 정상·실패 경로에서 작업 등록을 한 번 해제합니다.

`FolioDocumentLibrary`가 현재 폴더의 자식 정렬과 이동 대상 폴더도 계산합니다. 화면은 현재 위치·휴지통 표시·선택한 작업만 소유하며 별도 목록을 저장하지 않습니다. 이동 대상에서는 현재 상위 폴더·대상 자신·대상의 하위 폴더를 제외합니다.

`WikiWorkspace` actor가 원문 변경의 단일 소유자입니다. 불변 파일 목록과 링크 변환 계획을 먼저 만들고, 파일 조정과 버전 재검사 후 배타적 이동으로 반영합니다. 폴더 전체의 버전에는 일반 파일·숨김 자식·빈 폴더가 포함됩니다. 서로 다른 파일의 변경은 단일 파일시스템 트랜잭션이 아니므로 반영 실패 시 버전을 확인해 복구하며, 복구가 확인되지 않으면 결과 불확실로 보고합니다.

원문 반영과 검색 목록 갱신의 결과를 구분합니다. 확정 영수증은 작은 작업 기록으로 유지하고, 정상 완료 후 생성 당시의 파일 동일성과 내용을 확인해 임시 원문 사본을 정리합니다. 결과가 불확실한 작업의 기록과 복구용 사본은 보존하며 자동 재실행하지 않습니다.

디렉터리의 자식 파일까지 조정하는 옵션과 이동 알림은 현재 SDK 계약을 따릅니다. [Apple 파일 조정](https://developer.apple.com/documentation/foundation/nsfilecoordinator), [디렉터리 이동 조정](https://developer.apple.com/documentation/foundation/nsfilecoordinator/writingoptions/formoving), [이동 후 file presenter 알림](https://developer.apple.com/documentation/foundation/nsfilecoordinator/item(at:didmoveto:)). 실제 실행 결과와 남은 환경 검증은 [검증 기록](RELEASE.md#검증-범위)에 명시합니다.
