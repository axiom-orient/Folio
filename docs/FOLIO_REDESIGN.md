# Folio 사용 흐름 · 2026-11-22

## 이번 화면 개편

자료함에서는 **자료를 찾고**, 문서 화면에서는 **읽거나 편집하고**, 질문 화면에서는 **원문 근거를 확인**한다. 같은 배경·글자 체계를 쓰고, 저장·가져오기 완료처럼 의미가 바뀌는 동작은 화면에서 구별한다.

[시안 A · 목록과 원문 중심](Design/EvidenceFlow-20261122/direction-a.png) · [시안 B · 추천 자료와 고정 탐색](Design/EvidenceFlow-20261122/direction-b.png)

두 시안은 같은 질문과 가상의 자료를 썼다. A의 평면 목록, 한 번만 나오는 문서 제목, 출처를 인용 앞에 두는 구성을 채택했다. B는 추천 자료 카드, 고정 탭, 반복 저장 버튼이 자료 공간을 줄였다. 실제 화면은 Folio의 기존 색상과 시스템 글자 크기를 사용한다. 생성된 저자·판본·본문은 디자인용 예시다.

| 화면 | 가장 먼저 할 일 | 보조 동작과 정확성 |
| --- | --- | --- |
| 자료함 선택 | 저장 위치와 이름을 보고 자료함 하나를 연다. | 현재 선택을 체크로 표시한다. 생성·가져오기와 관리는 분리한다. |
| 문서 목록 | 제목과 짧은 발췌로 읽을 문서를 고른다. | ‘자료 추가’에서 PDF·Markdown 가져오기 또는 새 노트 작성을 시작한다. 같은 제목은 폴더를 표시한다. |
| 문서 검색 | ‘노트 검색’에서 해당 원문 위치를 찾는다. | 검색 입력 아래 ‘PDF·노트 근거 찾기’에서 자료함 전체의 PDF와 노트를 검색한다. 노트 검색의 활성 범위와 해제, 부분 검색 경고는 유지한다. |

| 편집 | 내용을 쓰고 필요한 변경을 저장한다. | ‘저장한 원문 보기’로 돌아가도 초안이 남는다. 변경된 원문 검토와 초안 폐기 확인은 그대로 이어진다. |

| 인용 원문 | PDF 페이지와 Markdown 구획에서 문맥을 확인한다. | 검색 결과와 저장 노트에서 같은 읽기 화면을 쓴다. 저장 인용은 현재 원문과 기록한 위치를 검증한 뒤 연다. 원문이 바뀌면 재검색을 안내한다. |
| 가져오기·새 문서·새 자료함 | 파일이나 제목과 실제 저장 대상을 확인하고 추가한다. | 처리 중의 대상 변경과 중복 제출을 기존 경계에서 검사한다. 실패 후 입력을 유지하며, 미확정 저장은 기존 결과를 확인한다. |
| 문서 정보·복구·공유 | 필요한 세부 정보나 예외를 해결한다. | 원문 ID·버전·관계 규칙·전송 상태는 각 보조 화면에서 확인한다. 원본·초안·영수증·승인 유효성은 기존 소유자가 관리한다. |

Mac과 iPad의 목록·본문 배치, iPhone의 목록에서 원문으로 이동했다가 돌아오는 구조를 유지했다. 사용성 검토의 근거는 [웹·공개 소스·논문 리서치](Research/folio-ux-evidence-research-20261122.md)에 있다. 시안은 동작 검증용 캡처가 아니다.

[시안과 iPhone 시뮬레이터 화면 대조](Design/EvidenceFlow-20261122/SIMULATOR_REVIEW.md)에 자료 추가부터 저장까지 조작한 경로와 수정 전후 화면을 기록했다. 초기 개편에서는 선택한 자동 테스트 23개가 통과했고 macOS 앱 UI 컴파일과 iOS 빌드를 완료했다. 저장 Markdown 인용과 중복 가져오기 정리는 [11월 27일 코드 검토](Research/folio-core-review-20261127.md)에 기록했다.

## 이전 사용 흐름 · 2026-11-08

첫 화면은 **읽기·쓰기·만들기**에 집중한다. 목록에서 문서를 바로 읽고, 편집 버튼으로 쓰며, 작성 버튼으로 새 문서 편집을 바로 시작한다. Mac은 Cmd-F로 검색, Cmd-N으로 작성한다. 문서가 차지하는 공간을 늘리고 정상 상태의 안내·폴더 위치·관계 목록·기술 설명을 본문 주변에 상시 쌓지 않는다.

검색은 돋보기로 연다. 폴더·태그·문서 정리·받은 파일·생성 옵션은 더 보기로 옮겼다. 활성 검색어와 필터, 저장 실패와 복구할 항목은 필요한 때 표시한다. 기본 검색은 원문에서 검색하며, ‘뜻으로 찾기’를 선택하면 입력한 질의를 바로 실행한다. 의미 검색 결과에는 제목과 짧은 발췌를 우선 표시한다. 모델 설명·점수·색인 수·작업 식별자는 정보에서 확인한다.

연결은 문서 옵션의 ‘연결된 문서’에서 연다. 규칙이 하나라면 제안을 바로 찾는다. 승인 화면은 연결할 두 문서와 두 근거를 보여주며 **명시 승인**을 받아야 원문을 변경한다. 정확한 변경 전·후 원문과 작업 식별자는 ‘원문 변경 상세’에 남겼다. 저장 결과가 미확정이면 자동 재실행하지 않는다.

2026-10-22 구조 정리에서 `WikiAppModel`의 자료함 자원 수명은 `FolioWorkspaceSession`, 새로고침·색인 작업은 `FolioWorkspaceJobs`로 분리했습니다. 파일 접근과 security-scoped lease의 정본은 기존 `WikiWorkspaceAccess`입니다. 세션 generation으로 이전 자료함의 늦은 응답을 거부합니다. 창별 선택과 문서 편집 명령의 조정은 앱 모델에 남습니다.

세션의 닫기 Task는 자원 해제와 닫기 등록 해제까지 마친 뒤 완료됩니다. `waitForClose` 이후의 열기·닫기가 이미 완료한 이전 작업 등록을 새 요청의 진행 상태로 보지 않도록 합니다.

현재 `FolioWorkspaceJobs`는 작업 ID와 Task를 하나의 `Job`으로 등록하고, 종료한 작업이 새 작업의 등록을 해제하지 않도록 ID를 확인합니다. 앱 모델은 선택·검색·목록 갱신을 조정하며 대기 이후 세션 generation을 확인합니다. 자료함 행의 저장 위치는 `FolioLibraryChoice`의 별도 상태로 저장하지 않고 위치 identity에서 계산합니다. iCloud 실패·충돌의 경고 우선순위와 문구는 같은 Notice 변환을 사용하며, 별도 주의 여부 플래그 없이 경고 값의 유무로 표시합니다.

2026-10-25에는 앱 모델에 남아 있던 상태와 작업을 소유권에 따라 분리했습니다. `FolioStorageAccess`는 저장소 준비·보호 데이터 가용성과 공유 준비 Task를 소유하고, 세션과 앱 모델은 같은 상태를 조회합니다. `FolioCloudAccount`는 계정 identity와 닫기·위치 해제를 끝까지 묶는 작업을 관리합니다. 해제 작업은 완료 전 교체하지 않는 Task 하나이며, 유효성 증거는 `FolioCloudIdentity`에만 둡니다. 자료함 자원 세대와 논리적 문서 맥락 세대는 세션에 두어 계정 변경 도중의 새 선택을 보존합니다.

`FolioFileIntake`는 첨부 연결 중복 방지, 수신 파일 반영 중 표시, 임시 복사본 수명과 미리보기를 소유합니다. 첨부 연결은 원문 반영·목록 갱신·창 선택까지, 수신 반영은 확인 후 보관까지 진행 상태를 유지합니다. 보류된 첨부 목록의 쓰기는 세션만 수행하며, 읽기 전후에 자료함 세대를 확인하고 실패하면 이전 목록을 유지합니다. `FolioDocumentReader`는 선택 원문 읽기와 revision별 자동 재조회 이력을 소유합니다. 읽기는 호출자의 Task에서 진행하며, 새 입력·선택·세션 변경 뒤의 늦은 결과와 오류를 거부합니다. 문서 조회는 세션의 projection에서 직접 수행하며 앱 모델의 조회를 Reader로 우회하지 않습니다. 앱 모델에는 창 등록과 전역 메시지·복구·충돌·병합 표시, 여러 소유자를 연결하는 명령 조정을 유지합니다. 이번 소스 정리에서는 빌드·테스트·기기 확인을 실행하지 않았습니다.

`FolioDraft`는 값 변환, `FolioDraftStore`는 편집 상태·입력 세대·저장 중 표시·debounce, `FolioDraftRepository`는 복구 JSON의 입출력을 담당합니다. 읽기·저장·병합·복구는 같은 입력 세대를 확인하며 Reader는 별도 편집 세대나 관찰 상태를 갖지 않습니다. 기존 복구 파일 경로·schema와 자료함 전환·background 시 동기 보존 시점은 유지합니다. 저장 완료 시 제출한 본문보다 새로운 입력을 보존하며 원문 저장의 CAS 권한은 KnowledgeKit에 있습니다. 스킬·플러그인의 경로와 소유권은 [설치 관리 계약](AGENT_MANAGEMENT.md)에 별도로 명시합니다.

문서 정리 전에 열린 모든 창의 편집·복구·버전 비교를 확인합니다. 원문 반영 후 목록을 갱신하며, 갱신 실패가 확정된 원문 변경을 취소한 것처럼 표시되지 않습니다. 이동한 문서의 선택·탐색 기록과 상대 링크를 갱신하고, 다른 문서를 읽는 창의 구획·읽기 위치는 유지합니다. 휴지통은 검색·원문 ZIP에서 제외합니다.

검색어와 필터는 창마다 독립적입니다. 조건이 바뀌면 이전 요청과 페이지를 무효화합니다. 다음 페이지 실패는 이미 표시한 결과와 재시도 위치를 보존하며, 원문 변경으로 만료된 페이지를 이어 붙이지 않습니다. 읽지 못한 원문은 부분 검색 표시와 복구 항목으로 드러납니다. 한 문서의 서로 다른 섹션은 별도 결과로 유지합니다.

Mac은 기존 HSplitView의 문서 목록과 본문, native selection·toolbar를 유지합니다. 목록에는 같은 paper 배경을 사용하고 선택 행의 보조 글자도 선명하게 표시합니다. iPhone은 하나의 NavigationStack, iPad는 split navigation을 사용합니다. iPhone 목록 상단에는 줄바꿈되는 현재 자료함 이름·전환, 더 보기, 새 문서를 한 영역에 배치하고 바로 아래에 검색과 폴더·태그를 둡니다. 조건을 선택했을 때만 실제 범위와 해제 동작을 표시합니다. 긴 자료함·문서 제목과 폴더 위치는 줄 수로 자르지 않습니다. reader의 전체 제목 위에 잘리는 탐색 막대 제목을 중복하지 않습니다. 문서의 paper와 브랜드 mark는 유지하며, 읽기 폭은 본문에 맞춰 제한합니다. 문서 정리와 받은 파일은 보조 메뉴에서 열고, 과거 수신 파일을 reader 아래에 상시 반복하지 않습니다. 현재 전송·승인 요청·확인이 필요한 결과와 오류는 유지합니다.

Notion의 [모바일 탐색](https://www.notion.com/help/workspaces-on-mobile)·[검색](https://www.notion.com/help/search), Obsidian의 [모바일 읽기·편집](https://obsidian.md/help/mobile), Bear의 [사이드바](https://bear.app/faq/about-the-sidebar-in-bear/)·[검색](https://bear.app/faq/how-to-search-notes-in-bear/)을 2026-10-22 확인했습니다. 탐색·검색·새 문서를 직접 찾을 수 있게 하고 문서에서 돌아오는 맥락을 보존하는 원리를 적용했습니다. Folio의 실제 저장 위치를 가진 자료함과 태그 필터의 권한·identity는 구분합니다. 이는 공개 안내를 바탕으로 한 Folio의 설계 판단이며 해당 앱의 모든 동작이나 시각적 유사성을 인증한 결과는 아닙니다.

`WikiWindowPresentation`은 시트·파일 열기·알림·미리보기를 공유하고, `FolioPresentation`과 `WikiDocumentLabels`는 공통 행·메시지·문서 표시를 담당합니다. `WikiLibraryPresentation`은 자료함 선택 시트를 닫은 뒤 선택한 작업을 실행하는 상태와 순서를 소유합니다. 창·외부 파일 추가·수신 파일 추가는 각 modifier 인스턴스에 독립된 대기 작업을 두고 같은 처리를 사용합니다. `FolioEditorContent`는 같은 원문 초안의 표시만 변환하며 독립 초안을 만들지 않습니다. `WikiRawEditor`의 native 입력·IME·undo owner는 유지하고 admission generation이 바뀐 이전 편집기의 입력은 새 세션에 넘기지 않습니다. 편집기 진입과 새 문서 본문 끝의 입력 초점을 구분합니다.

앱 아이콘과 내부 브랜드 mark는 펼친 책과 책갈피 하나로 읽기·기록·보관을 나타냅니다. 짙은 녹색과 아이보리 두 색을 사용하며 점·연결선·그라데이션을 제거했습니다. `FolioTheme.swift`의 editable Path를 `./script/render_assets.sh`로 내보내 Mac ICNS·크기별 PNG·iOS 불투명 1024px PNG·asset catalog를 함께 갱신합니다. 현재 앱 아이콘은 AppIcon·FolioIcon 경로를 사용합니다.

자료함 변경 전 복구본을 보존합니다. 저장 중 더 새로 입력된 초안은 버리지 않습니다. 늦은 링크·검색·근거 응답이 새 선택을 덮어쓰지 않으며 파일·사진을 추가할 때 원래 대상 자료함을 확인합니다. 초안 버리기는 현재 대상과 내용을 확인합니다.

원문 bytes·ID·CAS·충돌 복사본·영수증과 기존 로컬 데이터 이관·sourcewiki 링크 계약을 유지합니다. 새 UI는 독립 writer나 자동 재실행 경로를 만들지 않습니다. 중복 root 표현·상시 설명·사용하지 않는 색 토큰을 정리하고, 자료함 생성과 선택·공유 모델을 역할에 따라 분리했습니다.
