# Mac·iPhone에서 파일 주고받기

같은 Apple 계정의 Mac과 iPhone에서 Folio를 열면 연결 준비와 기기 검색을 앱이 맡는다. 처음에는 OS의 로컬 네트워크 접근 허용이 필요하다. 연결키 생성·지문 확인·연결 파일 전달·전송 시작 화면은 사용하지 않는다.

## 보내기

문서의 **문서 옵션**(Mac에서는 **문서 작업**)에서 **기기로 보내기 → 받을 기기**를 선택한다. 저장한 Markdown을 복사해 보낸다. 미저장 편집이 있으면 메뉴는 **저장한 문서 보내기**로 표시하며 초안은 그대로 유지한다. 자료함 전체는 **자료함 → 관리 → 자료함을 기기로 보내기**, 일반 파일은 **다른 파일 보내기…**를 사용한다. 파일과 실제 발견한 기기를 확인하고 대상을 선택한다. 별도 재확인은 없다. 기기 목록은 닫히고 읽던 문서에서 준비·진행·완료 또는 결과 확인을 표시한다. 준비 중에는 취소할 수 있다.

받는 기기에 Folio가 열려 있어야 한다. iCloud 키체인이 아직 도착하지 않으면 Mac의 Folio를 열고 잠시 후 **연결 다시 준비**를 사용한다. 한 번에 파일 하나, 최대256MiB다. 동일 iCloud 자료함을 계속 함께 사용할 때는 원래 iCloud 동기화를 사용하고 개별 파일 전송을 반복할 필요가 없다.

## 받기와 자료함 추가

읽던 화면에 파일명·크기·보낸 기기와 **받기 / 거절**이 나타난다. 저장이 끝나면 **받은 파일** 목록에서 파일을 선택해 상세를 연다. **받은 파일 → 선택한 파일**은 파일·종류·대상을 표시하며 **문서 추가 / 첨부 추가 / 가져오기** 중 하나를 제공한다. ZIP은 새 로컬 자료함으로 복원한다. 자료함이 필요한 파일은 먼저 선택할 수 있다. 수신만으로 원문을 자동 변경하지 않는다.

도구 막대의 **받은 파일**에서 수신 목록을 다시 열 수 있다. Markdown/ZIP 또는 첨부·연결 노트의 추가가 확인되면 자동으로 보관한다. 보관한 파일도 다시 공유하거나 가져올 수 있다. 파일 옵션의 보관/복원은 가역 이동이며 실제 bytes와 전송 receipt를 유지한다. 기존 파일·같은 ID 문서는 덮어쓰지 않는다.

수신 파일의 화면 표시와 반영 경로는 같은 분류를 사용한다. `md`·`markdown`은 문서, `zip`은 자료함, 나머지는 첨부로 분류하며 확장자 대소문자를 구분하지 않는다. 파일·영수증 검증과 대상 자료함 재확인은 반영 경로에서 별도로 유지한다.

수신을 마친 원본이 남았지만 최종 저장 기록이 만들어지지 않은 파일은 **받은 파일 → 저장을 마칠 수신 파일**에 표시한다. **저장 다시 시도**는 같은 전송 ID의 원본·완료 기록·파일 해시를 다시 확인한 뒤 저장을 마무리한다. 이미 저장한 파일과 보관한 파일을 덮어쓰지 않으며 자동으로 재실행하지 않는다. 원본 확인에 실패한 항목은 진단만 표시하고 그대로 보존한다.

복구 목록 조회는 원본과 기록을 바꾸지 않는다. 목적지에 이미 있는 파일의 사용량과 아직 원본 보관 단계인 파일을 구분하므로, 보존된 원본이 많아도 활성 보관 한도 안에서 하나씩 복구할 수 있다. 저장 재시도·복원은 진행 중인 수신 저장이 끝난 뒤 실행하며, 로컬 변경 작업 중에는 새 수신을 승인하지 않는다.

로컬 저장 결과를 표시한 뒤에도 원격 영수증 응답을 보내는 동안 수신 예약은 유지한다. 앱은 같은 관찰 스트림에서 예약 해제를 확인한 뒤 목록을 다시 읽으므로, 일부 저장으로 남은 원본과 재시도 버튼이 화면을 다시 열지 않아도 갱신된다. 내부 알림에는 최신 해제 세대를 함께 전달해 버퍼에서 알림 하나가 생략돼도 후속 알림으로 재조회할 수 있다. 구독 시작 시에도 현재 세대를 전달한다. 먼저 시작한 목록 조회는 더 최근 재조회 결과를 덮어쓰지 않는다. 완료·실패·취소의 기존 의미와 공개 이벤트 순서는 유지한다.

관찰 갱신과 저장 재시도 전 조회는 `FolioNearbyModel.reloadInventory` 한 곳에서 화면 목록에 반영한다. 재시도 전 한도 확인이 실패해도 이전 조회가 새 목록을 덮어쓰지 않는다. 해제 세대는 목록 반영에 성공한 뒤에만 처리 완료로 기록하므로, 실패하거나 더 최근 요청에 밀린 조회는 후속 알림에서 다시 확인한다. 실제 파일 저장·재시도 권한은 기존 Acornry store에 유지한다.

## 앱이 처리하는 준비와 복구

Mac이 최초256비트 난수 키를 synchronizable Keychain에 만들고 iPhone은 동일 항목을 읽는다. iPhone이 독립 키를 자동 생성하지 않는다. 기존 키는 교체하지 않는다. Apple Bonjour/P2P의 TLS PSK 전송을 사용하며 평문/Wi-Fi Aware fallback은 없다. 공유키 그룹 인증이며 표시 이름은 연락처 인증이나 개별 기기 인증서가 아니다.

화면 이탈·시트 닫기는 연결을 중지하지 않는다. iOS의 실제 scene disconnect만 해당 창을 detach하며 일시적인 root view disappearance는 전송을 종료하지 않는다. Mac의 마지막 창 종료/명시적 Quit, iPhone background에서 admission을 닫고 실제 작업을 drain한다. foreground에서 다시 준비한다. background 전송 완료는 보장하지 않는다.

송신 작업은 완료·실패·취소로 끝날 때 임시 송신 사본을 정리한다. 같은 세션 generation의 작업만 진행 중 상태와 작업 등록을 해제하므로 이전 작업의 종료가 새 세션 상태를 지우지 않는다. 결과 불명으로 보류한 새 송신은 기존 작업의 명시적 결과 확인 뒤에만 다시 허용한다.

중지 Task는 전송·관찰·등록된 복사/송신 작업의 종료, 최종 상태 읽기, 연결과 작업 등록 해제까지 마친 뒤 완료된다. 다시 준비하는 요청과 중복 중지 요청은 같은 전체 종료를 기다린다.

수신 저장 재시도·보관·복원·결과 조회도 실제 요청 Task로 등록해 호출자의 결과 처리까지 기다린다. 네트워크가 시작되지 않았거나 시작에 실패한 상태에서도 등록된 로컬 파일 작업을 종료 대기에서 제외하지 않는다. 서비스의 중지 등록이 해제되기 전에는 새 로컬 변경 작업을 받지 않는다.

Folio의 iOS 자체 저장 공간은 **재부팅 후 최초 잠금 해제까지 보호**하는 Apple Class C 정책을 사용한다. 디스크 암호화는 유지하고 이후 화면 잠금마다 앱 화면을 가리지 않는다. 기존 private 파일의 보호 속성만 한 번 UI 밖에서 갱신하며 bytes/ID/receipt는 변경하지 않는다. 일시 실패는 다음 실행/foreground에서 다시 준비한다. iCloud/provider 원문 정책과 macOS 미러링 로그인 인증은 앱이 변경하지 않는다. 전송 키도 AfterFirstUnlock Keychain 항목으로 유지한다. KnowledgeKit의 기본 private 저장 정책은 complete이며 Folio가 `KnowledgeDataProtection=after-first-unlock`로 선택한다. 앱의 일반 Data Protection entitlement는 그대로이고, 소유한 저장 디렉터리에 선택 정책을 명시한다.

active inbox64건/1GiB와 실제 디스크 여유를 확인한다. 보관은 삭제나 디스크 공간 회수가 아니다. 전송 후 응답을 잃으면 **전송 확인 필요**로 표시한다. 원래 기기와 동일 ID/manifest 결과만 조회하고 새 전송으로 자동 재시도하지 않는다. 새 송신은 실제 동일 operation 결과가 확인될 때까지 막으며, 낡은 snapshot만으로 해제하지 않는다. 일부 저장은 완료와 구별한다.

`FolioNearbyModel`은 연결과 관찰·송신·중지 작업의 세대 및 공통 작업 진입을 소유한다. 복사·송신 Task와 호출자가 기다리는 수신 재시도·보관·결과 확인은 활성 `Work` 하나에 등록하고, 진행 중 표시와 로컬 취소 가능 여부도 여기서 계산한다. 중지 중에는 새 작업을 등록하지 않으며, 권한 제한은 등록된 복사·송신 Task를 취소하고 중지는 이 Task들을 기다린 뒤 등록을 해제한다. 수신 영수증 목록은 `FolioReceivedFiles` 값 하나로 갱신하며, 이 타입이 수신·복원 한도와 영수증에 포함된 파일 조회를 담당한다. 목록을 읽은 뒤 같은 세션인지 확인하고 표시 상태에 반영한다. 보관된 실제 파일과 영수증의 저장 권한은 Acornry에 유지한다.

Acornry 내부의 `AcornryNearby`는 연결·handshake·작업 예약·중지와 관찰 상태를 소유한다. `AcornryOutgoingTransferSession`은 송신 프레임·결과 조회·journal의 결과 불명 경계를, `AcornryIncomingTransferSession`은 승인·수신 프레임·staging 완료·저장과 영수증 응답을 담당한다. 세션은 기존 예약 Task와 actor 격리 안에서 실행하며 별도 작업이나 상태 저장소를 만들지 않는다. 진행 상태와 수신 제안은 내부 이벤트를 통해 같은 façade에 반영한다. 송신의 영속 결과 불명 기록은 `transferEnd`보다 먼저 남기며, 수신의 로컬 완료는 원격 영수증 전달보다 먼저 확정한다.

송신 화면의 `FolioSendPreparation`은 원문 내보내기에서 준비한 임시 사본과 오류·준비 상태를 소유한다. 준비는 화면 Task의 취소를 따르고, 화면이 닫히면 남은 사본을 정리한다. 전송 모델이 보내기를 수락한 경우에만 사본을 인계하며, 이후 정리는 전송 작업이 담당한다.

실제 실행 범위는 [Current](RELEASE.md#검증-범위)를 따른다. Acornry는 전송·수신 bytes·delivery receipt를, KnowledgeKit은 위키 source/CAS·원문 receipt를 소유한다.
